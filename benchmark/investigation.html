1. Problem

id là PRIMARY KEY (có index tự động). pk_clone chứa cùng value với id, nhưng query trên pk_clone có thể chậm hơn. Dữ liệu sinh bằng generate_series(1, N), với id = pk_clone.

SELECT * FROM benchmark_table WHERE id = ?;
SELECT * FROM benchmark_table WHERE pk_clone = ?;

State 1: PK → Baseline; State 2: pk_clone WITHOUT INDEX → Reproduce problem; State 3: pk_clone WITH INDEX → Solution / Verification.

3. Assumption

Assumption (trước verification): pk_clone có thể chậm vì không có index, khiến PostgreSQL sử dụng Seq Scan thay vì Index Scan. Đây là giả thuyết; execution plan và metrics thực đo bên dưới sẽ kiểm chứng.

6. Solution

CREATE INDEX idx_benchmark_table_pk_clone
ON benchmark_table(pk_clone);

Tạo index trên chính cột trong điều kiện WHERE; chạy ANALYZE sau khi tạo index để cập nhật thống kê planner, không ép execution plan.
